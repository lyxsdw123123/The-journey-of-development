# 3. Python 内存管理

> 配套可运行脚本：`3. Python内存管理.py`

## 0. 一句话结论

**Python 的内存由「私有堆」（Private Heap）统一管理，里面存放所有 Python 对象；变量只是命名空间里的「名字 + 指针」，真正占内存的是对象。**

---

## 1. Python Private Heap

Python 的内存主要由一块**私有堆（Python Private Heap）**构成，所有 Python 对象都住在里面：

```text
        Python Private Heap（私有堆）
        ┌─────────────────────────────┐
        │  Integer 对象  100          │
        │  List 对象  [1, 2, 3]      │
        │  String 对象  "hello"      │
        │  ... 所有 Python 对象 ...   │
        └─────────────────────────────┘
                     ↑
                     │ 指向
        变量表（命名空间）
        ┌──────────────────┐
        │  x ──────────────┤
        └──────────────────┘
```

> 「私有」指这块内存由 Python 的内存管理器统一申请和释放，不直接暴露给用户，也不被操作系统直接管理。

---

## 2. 变量 vs 对象：谁占内存

```python
x = 100
```

```text
变量表（很小）              私有堆（占内存）
------------                ---------------
x  ────────────────→        Integer 对象
                            100
                            （值 + 类型 + 引用计数）
```

- **变量本身很小**：只是一个名字 + 一个指针（8 字节），存在命名空间里。
- **对象才占内存**：每个对象 = 数据 + 对象头（类型信息 + 引用计数）。

用 `sys.getsizeof` 验证：

```python
import sys
x = 100
print(sys.getsizeof(x))       # 28 字节（一个小整数对象）
print(sys.getsizeof(10**100)) # 更大，因为大整数按位数存储
```

---

## 3. 对象的组成

每个 Python 对象（CPython 实现）大致包含：

```text
┌──────────────────────┐
│  引用计数 (ref_count) │  <- 有多少地方在引用它
├──────────────────────┤
│  类型指针 (type)      │  <- 指向 int/list/str 等类型对象
├──────────────────────┤
│  数据本身             │  <- 真正的值
└──────────────────────┘
```

这就是「对象头」的固定开销。即使一个空列表，也要先占这部分空间：

```python
import sys
print(sys.getsizeof([]))   # 56 字节（64位系统）—— 光对象头就这么大
```

---

## 4. 容器对象存的是「指针数组」

列表并不直接「装」数据，而是装**指向元素的指针**：

```python
import sys
print(sys.getsizeof([]))        # 56
print(sys.getsizeof([1]))       # 64  = 56 + 1×8
print(sys.getsizeof([1,2,3]))   # 88  = 56 + 4×8（多预留了 1 个槽位）
```

```text
[1, 2, 3] 这个列表：
┌────────────┐
│ 对象头 56B │
├────────────┤
│ 指针 -> 1  │  8 字节
│ 指针 -> 2  │  8 字节
│ 指针 -> 3  │  8 字节
└────────────┘
```

> **关于列表的预分配（overallocation）**：`[1,2,3]` 实际是 88 字节，不是 56 + 3×8 = 80，因为列表会**预分配多余容量**，为后续 `append` 预留空间，避免频繁扩容。所以 `getsizeof` 反映的是「分配容量」，可能大于「实际元素数」。

> **关键**：`sys.getsizeof(容器)` 只算容器自身，**不算元素引用的对象**。所以 `[1000, 2000, 3000]` 里那 3 个大整数对象各自占的内存，不会被 `getsizeof` 统计进去。

---

## 5. 小整数缓存

CPython 启动时会**预先创建** `-5 ~ 256` 之间的所有整数并缓存，之后用到这些值直接复用：

```python
a = int("100")     # 100 在缓存内 -> 复用预创建的对象
b = int("100")
print(a is b)      # True

c = int("1000")    # 1000 超出缓存 -> 各建新对象
d = int("1000")
print(c is d)      # False
```

> 用 `int("...")` 动态生成是为了避开编译期「常量折叠」——如果直接写 `a = 100; b = 100`，编译器会把两个常量合并成同一个对象，导致结果干扰判断。

---

## 6. 内存分配器：pymalloc 分层管理

CPython 不从操作系统逐字节申请内存，而是用 **pymalloc** 分层管理：

```text
Arena（大块，如 256KB）
   └── Pool（中块，如 4KB）
         └── Block（小块，按对象大小分类）
```

好处：

1. **小对象分配/释放极快**——几乎只是移动指针，不频繁调用系统 `malloc/free`。
2. **减少系统调用**——一次申请一大块，内部慢慢分。
3. **缓存友好**——同类大小的对象集中存放。

这也解释了：**Python 创建大量小对象很快，但释放的内存未必立刻还给操作系统**（私有堆会留着复用）。

## 8. 小结

| 层次 | 关键词 | 记住什么 |
|------|--------|----------|
| 私有堆 | Private Heap | 所有对象统一住在这里 |
| 变量 vs 对象 | 名字/指针 vs 对象 | 变量很小，对象占内存 |
| 对象组成 | 引用计数 + 类型 + 数据 | 每个对象都有固定开销 |
| 容器 | 指针数组 | 容器存指针，不存数据 |
| 缓存 | 小整数 -5~256 | 高频小整数被复用 |
| 分配器 | pymalloc 分层 | 小对象分配极快 |

**核心认知**：对象才占内存，变量只是指向对象的指针；每个对象都背着「引用计数 + 类型」的对象头。
