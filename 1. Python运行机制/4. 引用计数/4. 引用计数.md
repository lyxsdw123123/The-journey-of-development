# 4. 引用计数（Reference Counting）

> 配套可运行脚本：`4. 引用计数.py`

## 0. 一句话结论

**CPython 最核心的内存机制是「引用计数」：每个对象记录被引用的次数，引用计数归零就立即释放对象——这是确定性的、即时的回收。**

---

## 1. 机制：每个对象都有一个计数器

```python
a = [1, 2, 3]
```

创建列表对象时，它的引用计数 = 1：

```text
列表对象
ref_count = 1    因为  a ---> list
```

```python
b = a
```

```text
        a ----\
               \
                list   ref_count = 2
               /
        b ----/
```

```python
del a
```

```text
        b ---> list   ref_count = 1
```

```python
del b
```

```text
        list 的 ref_count = 0  ->  Python 立即释放对象
```

---

## 2. 用 `sys.getrefcount` 查看

```python
import sys
a = [1, 2, 3]
print(sys.getrefcount(a))   # 2
```

> **坑**：返回值比「真实引用数」多 1，因为把 `a` 传给 `getrefcount` 时，参数本身又临时创建了一个引用。所以**真实值 = 返回值 - 1**。

逐个操作看变化：

```python
a = [1, 2, 3]
print(sys.getrefcount(a))   # 2  （真实值 1）

b = a
print(sys.getrefcount(a))   # 3  （真实值 2）

container = [a]
print(sys.getrefcount(a))   # 4  （真实值 3）

del b
print(sys.getrefcount(a))   # 3  （真实值 2）

del container
print(sys.getrefcount(a))   # 2  （真实值 1）
```

---

## 3. 哪些操作会改变引用计数

| 操作 | 效果 | 例子 |
|------|------|------|
| 赋值给名字 | +1 | `b = a` |
| 放进容器 | +1 | `lst.append(a)`、`d[key] = a` |
| 函数传参 | 临时 +1（返回后 -1） | `f(a)` |
| 从容器移除 | -1 | `lst.remove(a)` |
| `del` 名字 | -1 | `del a` |
| 离开作用域 | -1 | 函数返回，局部变量失效 |

---

## 4. 归零即释放（确定性回收）

引用计数是**即时**的：一归零，对象立刻被销毁，`__del__` 立即被调用。

用「弱引用」观察对象的生死：

```python
import weakref

class Foo:
    def __del__(self):
        print("被销毁了！")

obj = Foo()
r = weakref.ref(obj)   # 弱引用：能看到对象，但不增加引用计数

print(r())   # <__main__.Foo object ...>  还活着
del obj
print(r())   # None  —— 已经死了！
```

> **`weakref`（弱引用）**：能「观察」对象，却不会让引用计数 +1，是观察对象何时被回收的利器。

---

## 5. 引用计数的优点与缺点

| 优点 | 缺点 |
|------|------|
| 回收**即时、确定**，不卡顿 | 每次赋值/删除都要维护计数，有开销 |
| 实现简单、可预测 | **无法处理循环引用**（见下一个知识点） |

> 循环引用是引用计数的致命盲区，这正是「垃圾回收器 GC」存在的原因——见 `5. 为什么需要垃圾回收GC`。

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| 引用计数 | 每个对象记录被引用次数 |
| `getrefcount` | 返回值 = 真实值 + 1 |
| 归零即释放 | 确定性、即时回收 |
| 弱引用 | 观察对象但不增加计数 |
| 局限 | 无法处理循环引用 |

**核心认知**：引用计数让 CPython 的回收「即时且确定」，但它搞不定循环引用——那是 GC 的活。
