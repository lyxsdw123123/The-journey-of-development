# 2. JOIN 连接查询

> 配套可运行脚本：`2. JOIN 连接查询.py`

## 0. 一句话结论

**JOIN 把多张表按 `ON` 条件「拼」到一起，是 SQL 的核心。`INNER JOIN`（只留匹配）和 `LEFT JOIN`（左表全留）必须非常熟。**

---

## 1. 两张表

```text
users                     orders
┌────┬──────┐             ┌────┬─────────┐
│ id │ name │             │ id │ user_id │
├────┼──────┤             ├────┼─────────┤
│ 1  │ Tom  │             │ 10 │ 1       │
│ 2  │ Jack │             │ 11 │ 1       │
│ 3  │ Amy  │             │ 12 │ 2       │
└────┴──────┘             └────┴─────────┘
```

JOIN：

```sql
SELECT users.name, orders.id
FROM users
JOIN orders
ON users.id = orders.user_id;
```

结果：

```text
Tom   10
Tom   11
Jack  12
```

---

## 2. 各种 JOIN 对比

| 类型 | 结果 |
|------|------|
| `INNER JOIN` | 只保留**两边都能匹配**的行 |
| `LEFT JOIN` | **左表全保留**，右表匹配不上补 `NULL` |
| `RIGHT JOIN` | **右表全保留**，左表匹配不上补 `NULL` |
| `FULL OUTER JOIN` | 两边全保留，匹配不上补 `NULL` |
| `CROSS JOIN` | 笛卡尔积（两两组合，行数 = 左×右） |

---

## 3. INNER JOIN（默认）

```sql
SELECT users.name, orders.id
FROM users
JOIN orders              -- 省略 INNER，默认就是 INNER JOIN
ON users.id = orders.user_id;
```

结果：`Tom-10、Tom-11、Jack-12`。**Amy 没订单，被丢弃。**

---

## 4. LEFT JOIN（后端最常用）

```sql
SELECT users.name, orders.id
FROM users
LEFT JOIN orders
ON users.id = orders.user_id;
```

结果：

```text
Tom   10
Tom   11
Jack  12
Amy   NULL    <- 没有订单，补 NULL
```

用途：**「列出所有用户，即使没有订单」**。后端列表页、统计报表大量使用。

---

## 5. 何时用哪个

- 只要「两边都有」的记录 → `INNER JOIN`
- 要「某一边全部」，缺的补 NULL → `LEFT JOIN`（或 `RIGHT JOIN`）
- 两边都要全 → `FULL OUTER JOIN`

> 记忆：`LEFT JOIN` 以 `FROM` 里的左表为准，左表每一行都保留。

---

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| JOIN | 按 ON 条件拼表 |
| INNER JOIN | 只留匹配行 |
| LEFT JOIN | 左表全留，缺的补 NULL |
| CROSS JOIN | 笛卡尔积 |

**核心认知**：JOIN 是「关系型数据库」的灵魂——数据分散在多张表里，靠 JOIN 按外键关系重新组合。`INNER` 和 `LEFT` 是后端最高频的两种。
