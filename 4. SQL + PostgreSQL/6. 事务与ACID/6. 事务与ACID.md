# 6. 事务与 ACID

> 配套可运行脚本：`6. 事务与ACID.py`

## 0. 一句话结论

**事务把多条 SQL 打包成「一个不可分割的整体」——要么全部成功（COMMIT），要么全部回滚（ROLLBACK）。它满足 ACID 四特性。**

---

## 1. 为什么需要事务

银行转账：

```text
A 账户 -100
B 账户 +100
```

**绝不能出现**：

```text
A -100
B 没加 100   <- 数据不一致，灾难
```

所以要用事务：

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;   -- 全部成功，一起生效
```

如果中间出问题：

```sql
ROLLBACK;  -- 全部撤销，回到事务前
```

---

## 2. BEGIN / COMMIT / ROLLBACK

| 命令 | 作用 |
|------|------|
| `BEGIN` | 开启事务 |
| `COMMIT` | 提交（所有改动生效） |
| `ROLLBACK` | 回滚（撤销所有改动） |

```text
BEGIN -> 改 A -> 改 B -> COMMIT     （成功路径）
BEGIN -> 改 A -> 出错 -> ROLLBACK   （失败路径，改动撤销）
```

---

## 3. ACID 四特性

| 特性 | 含义 | 对应 |
|------|------|------|
| **A**tomicity 原子性 | 要么全成功，要么全回滚 | COMMIT/ROLLBACK |
| **C**onsistency 一致性 | 事务前后数据都满足约束 | 约束 |
| **I**solation 隔离性 | 并发事务互不干扰 | 锁 + MVCC（第 7、8 节） |
| **D**urability 持久性 | 提交后永久保存，断电不丢 | WAL、落盘 |

> 重点理解 **Atomicity**（原子性）——转账、下单扣库存等场景，必须「同生共死」。

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 事务 | 多条 SQL 打包成原子操作 |
| COMMIT | 提交生效 |
| ROLLBACK | 回滚撤销 |
| ACID | 原子/一致/隔离/持久 |

**核心认知**：事务是「数据一致性」的基石。后端凡是「多步修改必须同生共死」的场景，都要用事务。隔离性（I）背后是锁和 MVCC，正是接下来的内容。
