# 3. 子查询与 CTE

> 配套可运行脚本：`3. 子查询与CTE.py`

## 0. 一句话结论

**复杂查询需要「套娃」：先算中间结果，再在其上继续查。子查询适合简单嵌套，CTE（`WITH`）适合复杂查询——更清晰、可复用。**

---

## 1. 子查询

```sql
SELECT *
FROM users
WHERE id IN (
    SELECT user_id
    FROM orders
);
```

内层子查询先执行，得到 `user_id` 列表，再拿它匹配外层。

常见位置：

- `WHERE id IN (子查询)`
- `SELECT (标量子查询)` —— 子查询返回单个值

---

## 2. CTE（Common Table Expression）

```sql
WITH user_orders AS (
    SELECT user_id, COUNT(*) AS count
    FROM orders
    GROUP BY user_id
)
SELECT *
FROM user_orders
WHERE count > 10;
```

CTE 用 `WITH ... AS (...)` 给中间结果起名，之后像查表一样用它。

---

## 3. 子查询 vs CTE

| | 子查询 | CTE |
|--|--------|-----|
| 写法 | 嵌套在语句里 | 提前定义、命名 |
| 可读性 | 复杂时难读 | 清晰，像写代码 |
| 复用 | 每次要重写 | 同一条 SQL 里可多次引用 |
| 适用 | 简单条件 | 复杂后端查询、数据分析、GIS 查询 |

**经验**：查询一旦超过「两层嵌套」，就用 CTE 拆开。

---

## 4. CTE 可复用

```sql
WITH user_orders AS (
    SELECT user_id, COUNT(*) AS cnt
    FROM orders
    GROUP BY user_id
)
SELECT users.name, user_orders.cnt
FROM users
LEFT JOIN user_orders ON users.id = user_orders.user_id;
```

同一个 CTE 定义一次，可以拿去 JOIN、过滤、多次使用。

---

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| 子查询 | 查询里嵌套查询 |
| CTE | `WITH` 命名中间结果 |
| 选择 | 复杂查询优先 CTE |

**核心认知**：子查询和 CTE 都是「分步查询」的手段。CTE 让复杂 SQL 变得可读、可维护、可复用，是后端和数据分析的必备技能。
