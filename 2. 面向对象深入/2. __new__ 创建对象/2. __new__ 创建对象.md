# 2. `__new__` 创建对象

> 配套可运行脚本：`2. __new__ 创建对象.py`

## 0. 一句话结论

**对象创建不是 `__init__` 一个人的事——真正流程是 `__new__` 分配内存创建对象，再由 `__init__` 给这个已存在的对象填充数据。**

---

## 1. 常见误解

很多初学者认为：**对象创建 = `__init__`**。

其实不是。真正的流程：

```text
User()
  ↓
__new__(cls)      真正分配内存、创建对象
  ↓
创建对象
  ↓
__init__(self)    给已存在的对象填充数据
  ↓
初始化完成
```

```python
class User:
    def __new__(cls):
        print("创建对象")
        obj = super().__new__(cls)   # 真正分配内存
        return obj                    # 必须返回这个对象
    def __init__(self):
        print("初始化对象")

user = User()
```

输出：

```text
创建对象
初始化对象
```

---

## 2. `__new__` 与 `__init__` 的分工

| | `__new__` | `__init__` |
|--|-----------|------------|
| 职责 | 创建对象（分配内存） | 初始化对象（填充数据） |
| 参数 | `cls`（类本身） | `self`（已创建的对象） |
| 返回值 | 必须返回实例 | 无返回值（默认 `None`） |
| 调用时机 | 先 | 后 |

`__new__` 负责：

```python
obj = super().__new__(cls)   # 真正分配内存，造出一个「空」对象
```

`__init__` 负责：

```python
class User:
    def __init__(self, name):
        self.name = name      # 给已存在的对象填数据
```

执行 `user = User("Tom")` 实际上：

```text
1. 调用 User.__new__(User)      -> 创建一个 User 对象（分配内存）
2. 调用 User.__init__(对象, "Tom") -> 设置 对象.name = "Tom"
3. 把这个对象绑定给 user
```

---

## 3. 为什么很少重写 `__new__`

1. 默认 `object.__new__` 已经够用，自动分配内存。
2. 绝大多数初始化需求，重写 `__init__` 就能满足。
3. 重写 `__new__` 要理解 `cls`/`self` 和返回值，容易踩坑。

但**高级场景**会用到 `__new__`：**单例模式**、不可变类型定制、元类等。

---

## 4. 单例模式：`__new__` 的经典应用

数据库连接池、全局配置、日志器，都希望「全局只有一个实例」：

```python
class Database:
    instance = None

    def __new__(cls):
        if cls.instance is None:
            cls.instance = super().__new__(cls)   # 第一次：创建
        return cls.instance                        # 之后：复用同一个

db1 = Database()
db2 = Database()

print(db1 is db2)   # True
```

```text
db1 ──┐
      ├──> 唯一的 Database 实例
db2 ──┘
```

原理：`__new__` 每次都检查「是否已经创建过」，没有才新建，有就直接返回同一个实例。

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| `__new__` | 分配内存、创建对象，返回实例 |
| `__init__` | 填充数据、初始化，返回 None |
| 顺序 | 先 new 后 init |
| 单例模式 | `__new__` 里只建一次、复用同一实例 |

**核心认知**：`__new__` 造「空壳」，`__init__` 装「内容」。理解这个顺序，才能真正看懂对象是怎么诞生的。
