# Dev Learning Notes（开发学习笔记组织规范）

把「学习一个知识点」沉淀成**可运行、可验证、可增量扩展**的笔记仓库，而不是一次性问答。

## 何时使用

当用户表达想「系统学习某个开发主题」，且产出要被长期积累（建目录、写文件、进 git）时，按本规范组织文件。典型场景：

- 「学习 Python 解释器执行流程」
- 「讲一下协程 / 内存模型 / 垃圾回收是怎么工作的」
- 「帮我整理一份 X 知识点的笔记」

## 目录结构约定

每个「主题」是一个顶层文件夹，主题下按「序号. 知识点」拆分子文件夹：

```text
<主题名称>/
├── 1. <知识点A>/
│   ├── 1. <知识点A>.py   # 可运行演示脚本
│   └── 1. <知识点A>.md   # 讲解文档
├── 2. <知识点B>/
│   ├── 2. <知识点B>.py
│   └── 2. <知识点B>.md
└── README.md             # 可选：主题内目录说明
```

规则：

1. 序号用 `1.`、`2.`、`3.` 前缀（数字 + 英文点 + 空格），保证文件系统按顺序排列。
2. 每个知识点一个文件夹，里面**至少**一对 `.py` + `.md`。
3. `.py` 负责「跑起来看」，`.md` 负责「读懂为什么」。
4. 后续新增知识点只追加新序号文件夹，**绝不重排已有序号**（保持链接/引用稳定）。

## .py 演示脚本规范

- 顶层 docstring 先写「一句话结论 + 流程图」，让读者知道这份脚本在讲什么。
- 用章节函数分段（如 `section(title)` 打印分隔线），按「源码 → 原理逐层 → 实验 → 小结」推进。
- 优先用标准库自证：讲解释器用 `tokenize` / `ast` / `dis`，讲性能用 `timeit`。
- 涉及外部环境差异时（如字节码指令名随 Python 版本变化），在脚本里明确说明。
- Windows 控制台中文乱码时，加 `sys.stdout.reconfigure(encoding="utf-8")`。
- **写完必须实际运行一遍**：以「无报错、输出完整」作为完成标准，而不是写完就算完。运行中暴露的编码、API 兼容等问题要当场修掉。

## .md 讲解文档规范

结构建议：

1. 开头一句话结论。
2. 完整流程/原理（配表格或图）。
3. 逐层拆解（对应脚本每一步的输出）。
4. 动手清单（可复制的命令/代码片段）。
5. 小结表格（层次 / 关键词 / 工具 / 记住什么）。

## 收尾必做

- 跑通 `.py` 并修掉所有报错（编码、API 兼容等）。
- 在仓库或主题级 README 的「知识点索引」里登记本次新增内容，保持目录可索引。
- 提交 git 时，commit message 写清「新增：<主题>/<知识点>」。
