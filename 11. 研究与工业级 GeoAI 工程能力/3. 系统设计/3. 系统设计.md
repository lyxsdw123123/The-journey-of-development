# 3. 系统设计

## 0. 一句话结论

**前面学了 Python、FastAPI、PostgreSQL、Redis、Docker、Linux，这一阶段要把它们「组合成一个系统」——关注 API 设计、数据库、性能、可靠性四个维度。**

---

## 1. GeoAI 系统架构

```text
                用户
                 ↓
              Nginx
                 ↓
             FastAPI
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    Redis     PostgreSQL   Agent
                           │
                 ┌─────────┼─────────┐
                 ↓         ↓         ↓
              LLM       GIS Tools   RAG
                           │
                    ┌──────┼──────┐
                    ↓      ↓      ↓
                  GDAL  PostGIS  OSM
```

---

## 2. API 设计

| 关注点 | 说明 |
|--------|------|
| REST API | 资源化设计（GET/POST/PUT/DELETE） |
| 状态码 | 200/201/400/401/404/500 |
| 认证 | JWT / API Key |
| 参数校验 | Pydantic |
| 错误处理 | 统一错误格式 |

---

## 3. 数据库

```text
事务（ACID）
索引（B-tree + GiST）
连接池（复用连接）
空间索引（加速空间查询）
查询优化（EXPLAIN ANALYZE）
```

---

## 4. 系统性能

| 维度 | 关注 |
|------|------|
| CPU / GPU | 计算资源 |
| 内存 | OOM |
| IO | 磁盘/网络读写 |
| 缓存 | Redis |
| 并发 | asyncio / 连接池 / 限流 |

---

## 5. 系统可靠性

```text
日志（记录发生了什么）
监控（CPU/内存/请求量）
异常处理（try/except、重试）
超时（别让一个慢请求拖死整个系统）
限流（防打爆）
```

---

## 6. 小结

| 维度 | 一句话 |
|------|--------|
| API 设计 | REST + 状态码 + 校验 |
| 数据库 | 事务 + 索引 + 连接池 |
| 性能 | 缓存 + 并发 |
| 可靠性 | 日志 + 监控 + 重试 + 限流 |

**核心认知**：系统设计不是「会用一个框架」，而是「把多个组件组合成一个稳定、可扩展、可诊断的整体」。前面每个组件都学了，这一节是把它们「拼装」起来的工程思维。
