# 4. 模型部署

## 0. 一句话结论

**模型部署是「你和普通 Python 后端开发产生明显区别的地方」——从 `client.chat(...)` 走向「模型 → GPU → 推理框架 → API Server → Docker → Linux」。**

---

## 1. 部署链路

```text
模型
 ↓
GPU
 ↓
推理框架（vLLM / PyTorch）
 ↓
API Server（FastAPI）
 ↓
Docker
 ↓
Linux
```

---

## 2. 核心组件

| 组件 | 作用 |
|------|------|
| Hugging Face | 模型库 |
| PyTorch | 深度学习框架 |
| CUDA | GPU 计算 |
| Transformers | 模型加载/推理 |
| vLLM | 高性能推理服务 |

---

## 3. 推理优化

```text
模型量化（降低精度换速度/省显存）
Batch（批量推理提高吞吐）
KV Cache（缓存注意力计算，加速生成）
```

---

## 4. 精度类型

| 精度 | 位数 | 说明 |
|------|------|------|
| FP32 | 32 位 | 全精度 |
| FP16 | 16 位 | 半精度 |
| BF16 | 16 位 | 脑浮点（训练常用） |
| INT8 | 8 位 | 量化 |
| INT4 | 4 位 | 极致量化 |

---

## 5. 真正要能回答的问题

```text
显存为什么不够？
模型为什么 OOM？
为什么 batch 越大吞吐越高？
为什么并发增加后延迟变高？
GPU 利用率为什么只有 30%？
```

**能回答这些问题，才是真正的模型部署能力。**

---

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| 链路 | 模型→GPU→推理框架→API→Docker |
| 优化 | 量化 / Batch / KV Cache |
| 精度 | FP32/FP16/BF16/INT8/INT4 |
| 能力 | 诊断 OOM/吞吐/延迟/GPU 利用率 |

**核心认知**：模型部署的本质是「在有限的显存和算力下，稳定地、高吞吐地服务模型」。懂精度、Batch、KV Cache，才能诊断 OOM 和性能问题——这是普通后端到「AI 工程师」的关键一步。
