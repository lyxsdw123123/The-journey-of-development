# 7. 最终项目结构

## 0. 一句话结论

**最终把 GeoAI 系统整理成规范的项目结构，`docker compose up` 一条命令跑起来。**

---

## 1. 目录结构

```text
GeoAI-System/
│
├── api/
│   ├── routes/
│   └── schemas/
│
├── agent/
│   ├── planner.py
│   ├── executor.py
│   └── tools/
│
├── model/
│   ├── inference.py
│   └── embedding.py
│
├── gis/
│   ├── raster.py
│   ├── vector.py
│   └── spatial.py
│
├── database/
│   ├── postgres.py
│   └── postgis.py
│
├── services/
│
├── tests/
│
├── Dockerfile
├── docker-compose.yml
└── README.md
```

---

## 2. 分层职责

| 目录 | 职责 |
|------|------|
| api | 路由 + schema（请求/响应模型） |
| agent | 规划 + 执行 + 工具 |
| model | 模型推理 + 向量化 |
| gis | 栅格 + 矢量 + 空间分析 |
| database | Postgres + PostGIS |
| services | 业务服务层 |

---

## 3. 启动与运行链路

```bash
docker compose up
```

```text
Browser
   ↓
FastAPI
   ↓
GIS Agent
   ↓
Geo Model
   ↓
PostGIS
   ↓
GIS Tools
   ↓
地图 + 分析结果
```

---

## 4. 动手清单

1. 按上面结构搭出骨架（先空目录 + `__init__.py`）。

2. 逐个模块填充：先 database → gis → model → agent → api。

3. 写 Dockerfile + docker-compose.yml，`docker compose up` 跑通。

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 分层 | api/agent/model/gis/database |
| 启动 | docker compose up |
| 链路 | 浏览器 → FastAPI → Agent → 模型 → PostGIS → 地图 |

**核心认知**：规范的项目结构是「工程化」的体现——每个模块职责单一、可测试、可替换。搭好这个骨架，你的 GeoAI 系统就从「demo」升级为「可维护的工程」。
