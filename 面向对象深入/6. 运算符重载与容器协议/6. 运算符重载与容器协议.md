## 0. 一句话结论

**Python 的运算符和内置函数，本质都由魔术方法支撑——`a + b` 就是 `a.__add__(b)`，`len(obj)` 就是 `obj.__len__()`。重写这些方法，让自定义对象用起来像内置类型一样自然。**

---

## 1. 运算符 = 魔术方法

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)
print(v1 + v2)   # Vector(4, 6)
```

```text
v1 + v2
   ↓
v1.__add__(v2)
```

---

## 2. 常用运算符对照表

| 表达式 | 魔术方法 |
|--------|----------|
| `a + b` | `__add__` |
| `a - b` | `__sub__` |
| `a * b` | `__mul__` |
| `a / b` | `__truediv__` |
| `a == b` | `__eq__` |
| `a < b` | `__lt__` |
| `a <= b` | `__le__` |
| `a > b` | `__gt__` |

```python
class Money:
    def __init__(self, amount):
        self.amount = amount
    def __eq__(self, other):
        return self.amount == other.amount
    def __lt__(self, other):
        return self.amount < other.amount

m1 = Money(100)
m2 = Money(200)
print(m1 < m2)   # True
```

## 3. 容器协议

| 表达式 | 魔术方法 |
|--------|----------|
| `len(obj)` | `__len__` |
| `obj[key]` | `__getitem__` |
| `x in obj` | `__contains__` |
| `for x in obj` | `__iter__` / `__next__` |

```python
class Deck:
    def __init__(self):
        self.cards = ["A", "K", "Q"]
    def __len__(self):
        return len(self.cards)
    def __getitem__(self, index):
        return self.cards[index]
    def __contains__(self, card):
        return card in self.cards

deck = Deck()
print(len(deck))      # 3
print(deck[0])        # A
print("A" in deck)    # True
```

---

## 4. 为什么要用运算符重载

让自定义对象用起来像内置类型，代码更自然、可读：

```python
# 不用运算符重载（别扭）
total = v1.add(v2).add(v3)

# 用运算符重载（自然）
total = v1 + v2 + v3
```

框架里无处不在：Django 的 `QuerySet` 支持 `|` 合并条件，Pandas 的 `DataFrame` 支持 `+` 等运算。

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| 运算符重载 | `a + b` → `a.__add__(b)` |
| 比较运算 | `==` → `__eq__`，`<` → `__lt__` |
| 容器协议 | `len` → `__len__`，`[]` → `__getitem__` |
| 价值 | 让自定义对象像内置类型一样自然 |

**核心认知**：运算符和内置函数都不是「魔法」，而是魔术方法的协议调用。掌握它们，你就能设计出优雅、直观的 API。
