# 6. AI 后端架构

> 配套可运行脚本：`6. AI 后端架构.py`

## 0. 一句话结论

**在你的 AI 后端里，Redis 站在 FastAPI 和 PostgreSQL/LLM 之间，负责缓存、限流、状态——加速响应、降低 LLM 成本。**

---

## 1. 架构图

```text
                 ┌─────────────┐
                 │   用户请求   │
                 └──────┬──────┘
                        ↓
                 ┌─────────────┐
                 │   FastAPI   │
                 └──────┬──────┘
                        ↓
              ┌───────────────────┐
              │    业务逻辑层      │
              └───────┬───────────┘
                      ↓
              ┌───────────────┐
              │     Redis     │
              │ 缓存/限流/状态 │
              └───────┬───────┘
                      ↓
          ┌───────────┴───────────┐
          ↓                       ↓
   PostgreSQL                    LLM
          ↓                       ↓
       业务数据                  AI结果
```

---

## 2. 对 GeoAI / LLM + GIS 后端，Redis 的用途

| 用途 | 说明 |
|------|------|
| LLM 结果缓存 | 相同问题直接返回 |
| 地图查询缓存 | 热门区域查询缓存 |
| 用户 Session | 登录态 |
| Token 限流 | 防 API 滥用 |
| 异步任务状态 | 任务进行中/完成 |
| Agent 运行状态 | 多步骤 Agent 的中间状态 |

---

## 3. 完整路线

> **Redis：掌握缓存、TTL、数据结构、异步 Python 客户端、限流、分布式锁，并能在 FastAPI + PostgreSQL + LLM 项目中实际使用。**

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 架构 | FastAPI → Redis → PG/LLM |
| Redis 角色 | 缓存/限流/状态 |
| GeoAI 用途 | LLM 缓存、地图缓存、限流 |

**核心认知**：Redis 是 AI 后端的「加速层」——把昂贵的 LLM 调用、热门查询变成内存读。你前面学的 asyncio + FastAPI + PostgreSQL + Redis 到这里完整串成了一条 AI 后端链路。
