# 1. Redis 是什么

> 配套可运行脚本：`1. Redis 是什么.py`（需本机已启动 Redis）

## 0. 一句话结论

**Redis 是一个速度非常快、主要把数据放在内存中的 Key-Value 数据库——本质上是一张巨大的内存哈希表。**

---

## 1. 最简单的例子

```python
redis.set("user:1001:name", "张三")
name = redis.get("user:1001:name")   # "张三"
```

相当于：

```text
"user:1001:name" → "张三"
```

---

## 2. 为什么这么快

| 原因 | 说明 |
|------|------|
| 内存存储 | 数据在内存里，不是磁盘 |
| 单线程 | 没有锁竞争 |
| 简单模型 | Key-Value，无复杂查询 |

常见性能：每秒几万 ~ 几十万次操作。

---

## 3. 定位：与 PostgreSQL 互补

| 数据库 | 用途 |
|--------|------|
| PostgreSQL | 持久化、关系查询（源数据） |
| Redis | 缓存、Session、计数、限流（热点、临时） |

典型分工：

```text
FastAPI → 先查 Redis（快）→ 没有 → 查 PostgreSQL → 回填 Redis
```

---

## 4. 动手清单

1. 先启动 Redis，再运行脚本：

   ```bash
   redis-server          # 启动 Redis
   python "1. Redis 是什么.py"
   ```

2. 自己试 `set` / `get` 一个键，再 `DEL` 掉它。

3. 挑战：为什么 Redis 快，但它不能取代 PostgreSQL 存业务数据？

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| Redis | 内存 Key-Value 数据库 |
| set/get | 核心操作 |
| 定位 | 缓存/临时，与 PG 互补 |

**核心认知**：Redis 用「内存 + 简单结构」换极致速度，所以它适合「高频读、可丢失或可重建」的数据，而不是业务源数据。
