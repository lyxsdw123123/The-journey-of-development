# 3. 缓存与 TTL

> 配套可运行脚本：`3. 缓存与 TTL.py`

## 0. 一句话结论

**缓存是 Redis 最重要的用途，配合 TTL（过期时间）自动失效。经典「缓存旁路」模式：查缓存 → 没有则计算/查库 → 回填缓存（带 TTL）→ 返回。**

---

## 1. TTL 过期时间

```python
redis.set("llm:result:长沙高校", result, ex=3600)
# ex=3600 表示：3600 秒后自动过期
```

```python
r.ttl(key)   # 查看剩余存活秒数
```

---

## 2. 缓存旁路（Cache-Aside）

```text
FastAPI
  ↓
查 Redis
  ↓
有没有缓存？
├── 有 → 直接返回
└── 没有
      ↓
     LLM / 数据库
      ↓
    得到结果
      ↓
    存入 Redis（带 TTL）
      ↓
    返回
```

```python
def get_answer(question):
    key = f"llm:{question}"
    cached = r.get(key)
    if cached:
        return cached, True      # 命中
    answer = call_llm(question)  # 未命中，调 LLM
    r.set(key, answer, ex=3600)
    return answer, False
```

---

## 3. 为什么 AI 后端特别常用

| 价值 | 说明 |
|------|------|
| 减少 LLM 调用 | 相同问题直接返回缓存 |
| 降低延迟 | 内存读比 LLM 推理快几个数量级 |
| 降低成本 | 少调 API |
| 自动过期 | TTL 保证不永久陈旧 |

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| TTL | 缓存自动过期 |
| 缓存旁路 | 查缓存 → miss 回填 |
| 价值 | 少调 LLM、低延迟、省成本 |

**核心认知**：Redis 缓存 = 「用内存换速度」。AI 后端用它缓存 LLM/GIS 结果，把昂贵的计算变成一次性的，之后都是内存读。
