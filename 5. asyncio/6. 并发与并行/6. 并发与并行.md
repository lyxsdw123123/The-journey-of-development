# 6. 并发与并行

> 配套可运行脚本：`6. 并发与并行.py`

## 0. 一句话结论

**asyncio 是「并发」（单线程、任务交替推进），不是「并行」（多核同时执行）。所以它加速 I/O 密集，但不加速 CPU 密集。**

---

## 1. 并发 vs 并行

```text
并发（Concurrency）：
  一个线程 -> Event Loop -> T1 T2 T3 轮流跑（交替推进）

并行（Parallelism）：
  多个 CPU 核心 -> 真正同时执行
```

```text
asyncio：一个线程 + Event Loop
   │
 ┌─┼─┐
 ↓ ↓ ↓
T1 T2 T3
```

---

## 2. asyncio 的优势来源

| 场景 | 效果 |
|------|------|
| I/O 密集（await sleep/网络/数据库） | 加速（并发，等待时切走） |
| CPU 密集（`for` 循环大量计算） | 不加速（单线程，计算不中断） |

```python
async def cpu_task():
    for i in range(100000000):   # 一直占着 CPU
        ...
```

这个任务一直占着 CPU：

```text
CPU Task ████████████████████
```

事件循环很难去处理其他任务——因为**没有 `await`，就不会让出**。

---

## 3. 正确选择

| 场景 | 方案 |
|------|------|
| CPU 密集 | `multiprocessing` / C 扩展 / NumPy（多核并行） |
| I/O 密集 | `asyncio` / 多线程（并发） |

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 并发 | 单线程交替推进 |
| 并行 | 多核同时执行 |
| asyncio | 并发，非并行 |
| 适用 | I/O 密集 |

**核心认知**：asyncio 用「单线程 + 事件循环」实现 I/O 并发，省的是「等待时间」，不是「计算时间」。CPU 密集要上多进程/多核。
