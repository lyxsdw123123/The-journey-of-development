# 5. Coroutine / Task / Future 区分

> 配套可运行脚本：`5. Coroutine Task Future 区分.py`

## 0. 一句话结论

**Coroutine 是要执行的异步函数；Task 是被事件循环调度的协程；Future 是「未来会产生结果」的容器。关系：`async def → Coroutine → Task → 调度 → Future/结果 → 完成`。**

---

## 1. 三者概念

| 概念 | 先这样理解 |
|------|-----------|
| Coroutine | 要执行的异步函数 |
| Task | 被 Event Loop 调度的协程 |
| Future | 一个未来会产生结果的容器/状态对象 |

---

## 2. 关系图

```text
async def
   ↓
Coroutine（协程对象）
   ↓  create_task
Task（交给事件循环）
   ↓
Event Loop 调度
   ↓
Future / I/O 结果
   ↓
完成
```

---

## 3. 代码里的类型

```python
import asyncio

async def foo():
    return 42

coro = foo()                 # <coroutine object>
task = asyncio.create_task(coro)  # <Task>
print(issubclass(asyncio.Task, asyncio.Future))  # True
```

- `Task` 是 `Future` 的子类——它本质是一个「驱动协程前进的 Future」。
- `Future` 是更底层的结果容器，通常你直接操作的是 `Task`。

---

## 4. `ensure_future` vs `create_task`

```python
task = asyncio.ensure_future(coro)   # 协程 -> Task；Future -> 原样返回
task = asyncio.create_task(coro)     # 更明确、更推荐
```

> 二者都能把协程包装成 Task，`create_task` 语义更清晰，现代代码推荐用它。

---

## 5. 为什么这组概念重要

读 FastAPI、aiohttp、数据库驱动源码时，你会频繁看到 Coroutine / Task / Future。分清它们，才能看懂「一个请求是怎么被包装、调度、拿到结果的」。

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| Coroutine | 异步函数 |
| Task | 被调度的协程（Future 子类） |
| Future | 未来结果的容器 |

**核心认知**：`async def` 产生协程，`create_task` 把协程变成可被调度、可被 await 结果的 Task。这条「包装链」是 asyncio 的对象模型核心。
