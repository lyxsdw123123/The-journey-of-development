# 8. FastAPI 异步机制与完整链路

> 配套可运行脚本：`8. FastAPI 异步机制与完整链路.py`

## 0. 一句话结论

**你的目标不是「会使用 asyncio」，而是「知道 FastAPI 为什么可以同时处理大量请求」——答案是：事件循环 + `async def` + `await` + 异步数据库驱动。**

---

## 1. 完整后端链路

```text
浏览器
  ↓
HTTP
  ↓
Uvicorn（ASGI 服务器，驱动事件循环）
  ↓
Event Loop
  ↓
FastAPI
  ↓
async def（你的路由处理函数）
  ↓
await
  ↓
异步数据库驱动（asyncpg 等）
  ↓
PostgreSQL
```

---

## 2. FastAPI 高并发的秘密

```python
@app.get("/users")
async def get_users():
    rows = await db.fetch("SELECT * FROM users")
    return rows
```

- 路由是 `async def`，数据库查询用 `await`。
- 等待数据库时，**事件循环去处理别的请求**，所以能同时扛大量连接。

> 注意：如果用普通 `def` 路由，FastAPI 会丢到线程池；`async def + await` 才是真正的异步并发。

---

## 3. 为什么这样设计（从会用 → 懂原理）

| 问题 | 答案 |
|------|------|
| 为什么路由要 `async def`？ | 让事件循环能调度它 |
| 为什么用 asyncpg？ | `await` 时不阻塞事件循环 |
| 为什么 Uvicorn 扛大量连接？ | 单线程事件循环 + I/O 并发 |
| 为什么不能用 `time.sleep`？ | 它会阻塞整个事件循环！ |

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 链路 | Uvicorn → 事件循环 → FastAPI → async/await → 异步DB |
| 高并发 | 等待时不阻塞，事件循环去处理别的请求 |
| 关键 | async def + await 异步驱动 |

**核心认知**：FastAPI 的高并发不是魔法，而是「事件循环 + 异步 I/O」。搞懂这一层，你之前用的 FastAPI、LangChain、异步 API 调用，都会从「会调用」变成「理解为什么这样设计」。
