# 1. 为什么需要 asyncio

> 配套可运行脚本：`1. 为什么需要 asyncio.py`

## 0. 一句话结论

**同步代码在等待 I/O 时 CPU 傻等；asyncio 让「等待 I/O 时把执行机会让给其他任务」，从而用一个线程处理大量并发 I/O。**

---

## 1. 同步代码的问题

```python
def get_user():
    data = database.query()   # 这里要等数据库
    return data
```

执行过程：

```text
请求 -> 执行 Python -> 数据库查询 -> 等待数据库返回 -> 继续执行 -> 返回结果
```

**关键问题**：等待数据库的时候，CPU 并没有做有意义的工作。

大量请求时：

```text
请求1 → 等数据库 ─────────→ 返回
请求2        → 等数据库 ─────────→ 返回
请求3               → 等数据库 ─────────→ 返回
```

同步模型产生大量「等待」，时间全浪费在等上。

---

## 2. asyncio 解决什么

异步模型：

```text
请求1 执行 -> 等待数据库
                 └─────── 让出机会
请求2 执行 -> 等待数据库
                 └─────── 让出机会
请求3 执行 -> ...
```

**核心思想：等待 I/O 的时候，不要傻等，把执行机会让给其他任务。**

---

## 3. asyncio 适合什么

| 适合（I/O 密集） | 不适合（CPU 密集） |
|------------------|--------------------|
| HTTP 请求 | 纯计算任务 |
| 数据库 | 矩阵运算 |
| Redis | 大量循环 |
| 文件 I/O | 图像处理 |
| 网络通信、WebSocket、API 调用 | —— |

> asyncio 的优势来自 **I/O 并发**，不是 CPU 加速（它是单线程，见第 6 节）。

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 同步 | 等 I/O 时 CPU 傻等 |
| 异步 | 等 I/O 时让出执行权 |
| 适用 | I/O 密集，非 CPU 密集 |

**核心认知**：asyncio 解决的是「I/O 等待浪费 CPU」的问题——用一个线程高效调度大量等待中的任务。这是理解后续协程、事件循环、Task 的出发点。
