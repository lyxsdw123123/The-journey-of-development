# 3. Event Loop 事件循环

> 配套可运行脚本：`3. Event Loop 事件循环.py`

## 0. 一句话结论

**Event Loop（事件循环）是 asyncio 的核心——一个不断循环的调度器：检查任务 → 谁能继续 → 执行 → 遇到 await 切换 → 再循环。**

---

## 1. 简化模型

```text
             Event Loop
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
     Task 1     Task 2     Task 3
       │          │          │
       ↓          ↓          ↓
     await      await       CPU
       │          │          │
       └──────┬───┘          │
              ↓
        Event Loop
              │
              ↓
       谁可以继续执行？
```

---

## 2. 事件循环做什么

```text
检查任务
   ↓
哪个任务可以继续？
   ↓
执行
   ↓
遇到 await / I/O 等待
   ↓
切换其他任务
   ↓
循环
```

一句话：**事件循环是一个「大 while 循环」，不断把 CPU 时间片分给那些「不再等待」的任务。**

---

## 3. `asyncio.run` 与事件循环

```python
asyncio.run(main())
```

内部做了：

```text
创建 Event Loop -> 运行 main() -> 关闭 Event Loop
```

```python
async def show_loop():
    loop = asyncio.get_running_loop()
    print(loop)

asyncio.run(show_loop())
```

---

## 4. 并发调度的效果

三个任务 A(3s)、B(1s)、C(2s) 并发：

```text
B 先完成（1s）-> C 完成（2s）-> A 完成（3s）
```

事件循环在 B 等待时去跑 C，在 C 等待时去跑 A——**不浪费等待时间**。

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| Event Loop | asyncio 的核心调度器 |
| `asyncio.run` | 创建并运行事件循环 |
| 循环逻辑 | 检查 → 执行 → 遇 await 切换 |
| 效果 | 等待不占 CPU，充分利用时间 |

**核心认知**：事件循环是「单线程内的调度器」，它靠「在 await 处切换任务」实现并发。理解这个循环，就理解了 asyncio 的心脏。
