# 1. Python 解释器执行流程

> 配套可运行脚本：`1. Python解释器执行流程.py`（建议边读本文边跑脚本）

## 0. 一句话结论

**Python 代码不是被「直接执行」的，而是被翻译成一种叫「字节码」的中间形式，再由 Python 虚拟机逐条解释执行。**

```text
.py 源码
    ↓
词法分析 (Token)
    ↓
语法分析 (AST)
    ↓
编译
    ↓
字节码 (Bytecode)
    ↓
Python 虚拟机 (PVM)
    ↓
CPU 执行
```

---

## 1. 完整流程概览

以这段代码为例：

```python
a = 1
b = a + 2
print(b)
```

它不会像 C 语言那样直接被编译成机器码，也不会像最原始的脚本语言那样一行行直接「读着跑」。CPython（官方 Python 解释器）走的是下面这条流水线：

| 阶段 | 输入 | 输出 | 作用 | Python 里怎么看 |
|------|------|------|------|----------------|
| 1. 源码 | 你写的文本 | 文本 | 起点 | 直接看 `.py` 文件 |
| 2. 词法分析 | 文本 | Token 序列 | 切词 | `tokenize` 模块 |
| 3. 语法分析 | Token | AST | 组织成树 | `ast` 模块 |
| 4. 编译 | AST | 字节码 | 生成中间指令 | `compile()` / `dis` 模块 |
| 5. 执行 | 字节码 | 结果 | 逐条解释 | Python 虚拟机 (PVM) |

---

## 2. 词法分析（Tokenization）

把连续的字符，切成一个个有意义的「词元（Token）」。切分时不关心语法是否正确，只关心「这个片段是什么东西」。

```python
a = 1
b = a + 2
print(b)
```

会被切分成类似：

```text
NAME      'a'
OP        '='
NUMBER    '1'
NEWLINE
NAME      'b'
OP        '='
NAME      'a'
OP        '+'
NUMBER    '2'
NEWLINE
NAME      'print'
OP        '('
NAME      'b'
OP        ')'
NEWLINE
```

常见 Token 类型：

- `NAME`：标识符（变量名、函数名、关键字）
- `NUMBER`：数字字面量
- `STRING`：字符串字面量
- `OP`：运算符（`= + - * ( )` 等）
- `NEWLINE`：换行
- `INDENT` / `DEDENT`：缩进（Python 特有，缩进也是语法的一部分）

动手实验：

```python
import io, tokenize

code = "a = 1\n"
for tok in tokenize.generate_tokens(io.BytesIO(code.encode()).readline):
    print(tokenize.tok_name[tok.type], repr(tok.string), tok.start)
```

---

## 3. 语法分析（Parsing → AST）

把 Token 序列组织成一棵「抽象语法树（Abstract Syntax Tree，AST）」。这一步会检查语法结构是否正确——**语法错误（SyntaxError）就是在这里被拦下来的**。

```python
import ast

code = "a = 1\nb = a + 2\nprint(b)\n"
tree = ast.parse(code)
print(ast.dump(tree, indent=2))
```

输出的树结构（简化）：

```text
Module
└── body
    ├── Assign          # a = 1
    │   ├── targets: [Name('a')]
    │   └── value: Constant(1)
    ├── Assign          # b = a + 2
    │   ├── targets: [Name('b')]
    │   └── value: BinOp
    │       ├── left: Name('a')
    │       ├── op: Add()
    │       └── right: Constant(2)
    └── Expr            # print(b)
        └── Call
            ├── func: Name('print')
            └── args: [Name('b')]
```

**AST 的意义**：它是「程序结构」的抽象表示。很多工具都建立在 AST 之上——IDE 的自动补全、Lint 工具（如 pylint）、代码格式化（如 black）、静态分析等。

---

## 4. 编译（Compile → 字节码）

AST 本身还不能执行，需要被「编译」成字节码。字节码是一种**面向 Python 虚拟机的低级指令**，基于「栈」来工作。

### 4.1 用 compile() 得到代码对象

```python
code = "x = 10\ny = x + 5\n"
code_obj = compile(code, filename="<demo>", mode="exec")
print(code_obj.co_consts)   # 常量表，如 (10, 5, None)
print(code_obj.co_names)    # 名字表，如 ('x', 'y')
```

`compile()` 返回一个「代码对象（code object）」，里面保存了常量、变量名、字节码等所有执行所需信息。

### 4.2 用 dis 反汇编查看字节码

```python
import dis

code = "x = 10\ny = x + 5\n"
dis.dis(compile(code, "<demo>", "exec"))
```

输出类似：

```text
  1           0 LOAD_CONST    0 (10)
              2 STORE_NAME    0 (x)

  2           4 LOAD_NAME     0 (x)
              6 LOAD_CONST    1 (5)
              8 BINARY_ADD
             10 STORE_NAME    1 (y)
             12 LOAD_CONST    2 (None)
             14 RETURN_VALUE
```

这正是你参考里的中间形式。逐行解读：

| 字节码 | 含义 |
|--------|------|
| `LOAD_CONST 10` | 把常量 `10` 压入栈 |
| `STORE_NAME x` | 弹出栈顶，存入变量 `x` |
| `LOAD_NAME x` | 把变量 `x` 的值压入栈 |
| `LOAD_CONST 5` | 把常量 `5` 压入栈 |
| `BINARY_ADD` | 弹出栈顶两个值相加，结果压回栈 |
| `STORE_NAME y` | 弹出栈顶，存入变量 `y` |

> **基于栈的执行模型**：字节码通过「压栈 / 弹栈」来传递数据，而不是像寄存器那样直接寻址。理解「栈」是理解字节码的关键。

### 4.3 函数的字节码（你参考里的 dis.dis(add)）

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```

输出类似：

```text
  2           0 LOAD_FAST    0 (a)
              2 LOAD_FAST    1 (b)
              4 BINARY_ADD
              6 RETURN_VALUE
```

解读：

- `LOAD_FAST a`：把局部变量 `a` 压入栈（`LOAD_FAST` 比 `LOAD_NAME` 快，因为它直接从局部变量数组按索引取值）
- `LOAD_FAST b`：把局部变量 `b` 压入栈
- `BINARY_ADD`：弹出两个值相加，结果压回
- `RETURN_VALUE`：弹出栈顶作为函数返回值

> 不同 Python 版本中，`BINARY_ADD` 可能显示为 `BINARY_OP`，这是版本间的实现差异，语义相同。**字节码是版本相关的**，这也是为什么不同版本解释器通常不共享 `.pyc` 缓存。

## 5. Python 虚拟机（PVM）执行

字节码不是 CPU 能直接执行的机器码，它是 **Python 虚拟机（Python Virtual Machine, PVM）** 的指令。

PVM 本质上是一个「取指令 → 解码 → 执行」的大循环：

```text
while True:
    指令 = 取出下一条字节码
    根据指令类型跳转到对应的 C 代码执行
    （可能会压栈、弹栈、调用函数、分配对象……）
```

- **编译型语言**（如 C）：源码 → 机器码 → CPU 直接执行。
- **解释型语言**（如 Python）：源码 → 字节码 → 虚拟机解释执行。

所以 Python 慢的一个根本原因就是：**每条字节码都要经过一层虚拟机调度，无法直接被 CPU 硬件执行**。这也是后来出现 PyPy（JIT 即时编译）、Cython、Numba 等技术来「绕开」这条慢路径的原因。

## 6. 为什么工程开发要懂字节码？

因为**很多性能问题就来自字节码层面**——同样的功能，字节码指令越少、越「专用」，执行越快。

### 6.1 例子：普通循环 vs 列表推导式

**低效写法：**

```python
result = []
for i in range(100000):
    result.append(i)
```

每一轮循环，解释器都要反复执行：

```text
LOAD      （取 result）
CALL      （查找并调用 append 方法）
STORE     （存回 result）
LOAD      （取 i）
CALL
STORE
...
```

其中 `append` 是**运行时动态查找的方法**，解释器无法预知它会不会被改掉，所以每次都老老实实查一遍、调一遍。

**高效写法：**

```python
result = [i for i in range(100000)]
```

列表推导式是**语言级语法**，解释器「知道」你要构建一个列表，于是用专门的 `LIST_APPEND` 字节码完成，跳过了反复的方法查找和调用，**优化空间更大**。

实测：同样的任务，列表推导式通常比 `for + append` 快不少（具体倍数见配套脚本的运行结果）。

### 6.2 三大成本

高级 Python 开发者会持续关注这三类开销：

1. **循环成本**
   - 每一轮循环都要执行一遍循环体内的多条字节码。
   - 优化：把热循环向量化，或改用内置函数（`sum` / `map` / 推导式）。

2. **函数调用成本**
   - 每次调用函数都要：压栈 → 建立栈帧（frame）→ 执行 → 弹栈。
   - 在极热路径（被执行几百万次）里，调用本身可能比函数体还贵。
   - 优化：减少不必要的函数封装，或使用 `@functools`、内联热点。

3. **对象创建成本**
   - 每个 `int` / `list` / `dict` 都要分配内存、初始化，最终还可能触发垃圾回收（GC）。
   - 优化：复用对象、避免不必要的中间结果、用生成器替代大列表。

> **心法**：当你怀疑某段代码慢时，先 `dis.dis()` 看字节码，再看算法。字节码是性能的第一手线索。

## 8. 小结

| 层次 | 关键词 | 工具 | 你该记住什么 |
|------|--------|------|-------------|
| 词法分析 | Token | `tokenize` | 代码先被切成词元 |
| 语法分析 | AST | `ast` | 语法错误在此拦截，工具链基于它 |
| 编译 | 字节码 | `compile` / `dis` | 字节码是栈式中间指令 |
| 执行 | PVM | 解释器本身 | 逐条解释，是慢的根源之一 |

**核心认知**：`LOAD_CONST / STORE_NAME / LOAD_FAST / BINARY_ADD / CALL` 这些字节码，就是 Python 性能问题的「显微镜」。读懂它们，你才真正理解 Python 是怎么跑起来的。
