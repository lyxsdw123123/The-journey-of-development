# 5. 为什么需要垃圾回收 GC

> 配套可运行脚本：`5. 为什么需要垃圾回收GC.py`

## 0. 一句话结论

**引用计数搞不定「循环引用」——两个对象互相引用时，引用计数永远不为 0。所以 CPython 还需要「垃圾回收器 GC」专门找出并释放这些不可达的循环。**

---

## 1. 循环引用：引用计数的致命盲区

```python
class Node:
    pass

a = Node()
b = Node()

a.next = b
b.next = a
```

此时的内存结构：

```text
a ──→ b
↑     │
└─────┘
```

引用计数：

```text
a 的 ref_count = 1   （b.next 指着 a）
b 的 ref_count = 1   （a.next 指着 b）
```

现在删除 `a` 和 `b`：

```python
del a
del b
```

结果：

```text
对象仍然互相引用！
        ┌─────┐
        │ Node │ ←──┐
        └─────┘    │
           │       │
           └───────┘
        外界已经够不到它们了，
        但 ref_count 仍是 1（互相指着），
        -> 无法释放！
```

**这就是循环引用（cyclic reference）。**

---

## 2. 垃圾回收器 GC 登场

GC 的职责：**找出「不可达」的对象（外界引用链够不到的对象），把它们释放。**

```text
可达（reachable）：从根（全局命名空间、栈、寄存器等）出发，能通过引用链走到。
不可达（unreachable）：从根走不到，但可能因循环引用而 ref_count > 0。
```

GC 的做法：

1. 找到所有「可达」对象，标记存活。
2. 其余对象即使互相引用，也是「不可达」的垃圾。
3. 释放这些不可达对象，打破循环。

```python
import gc
n = gc.collect()   # 手动触发一次完整回收，返回回收的对象数
```

---

## 3. 分代回收（Generational GC）

GC 不是每次都扫描全部对象，而是分 3 代：

| 代 | 特点 | 扫描频率 |
|----|------|----------|
| gen0 | 新对象 | 最频繁 |
| gen1 | 活过几次 gen0 的对象 | 中等 |
| gen2 | 老对象 | 最少 |

```python
import gc
print(gc.get_count())      # 每代待回收的对象数
print(gc.get_threshold())  # 触发阈值（默认 700, 10, 10）
```

直觉：

- **大多数对象很快死亡**（函数返回就死了），所以主要扫 gen0，成本低。
- **活得越久越可能是常驻对象**，扫得越少越省时间。

> 一个对象如果在一次 gen0 扫描中存活下来，就「晋升」到 gen1；gen1 再存活晋升到 gen2。

---

## 4. 用弱引用观察循环引用的回收

```python
import gc
import weakref

class Node:
    def __init__(self, name):
        self.name = name

a = Node("A")
b = Node("B")
a.next = b
b.next = a

ra = weakref.ref(a)
rb = weakref.ref(b)

del a
del b

print(ra())        # 还在！<Node A>（循环引用，引用计数没归零）
gc.collect()       # GC 出手
print(ra())        # None —— 已被回收
```

## 5. 工程实践：何时手动 gc

| 场景 | 做法 |
|------|------|
| 绝大多数情况 | 不用管，GC 自动跑 |
| 内存持续上涨、怀疑泄漏 | `gc.collect()` 排查 |
| 大量临时对象、性能敏感 | 高级用法：`gc.disable()` + 手动 `gc.collect()` |

> **原则**：优先写干净代码（用 `with`、及时 `del`、避免不必要的全局引用），而不是依赖手动 `gc`。GC 是兜底，不是日常工具。

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| 循环引用 | 对象互相引用，引用计数永不归零 |
| GC | 回收不可达对象，打破循环 |
| 分代回收 | gen0 频繁扫，gen2 少扫 |
| 可达性 | 从根出发能否走到 |
| 手动 gc | 兜底/排查，不常用 |

**核心认知**：引用计数负责「即时回收单个对象」，GC 负责「兜底回收循环引用」。两者配合，CPython 才能自动管理内存。
