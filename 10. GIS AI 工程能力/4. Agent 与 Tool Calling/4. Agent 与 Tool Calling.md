# 4. Agent 与 Tool Calling

## 0. 一句话结论

**Agent 不是「调一下 agent.invoke()」，而是一个循环：LLM 推理 → 选择工具 → 调用工具 → 观察结果 → 再推理 → 直到得出最终答案。核心思想：LLM 负责决策，工具（如 PostGIS）负责真正计算。**

---

## 1. Agent 循环

```text
User
 ↓
LLM（推理）
 ↓
Reasoning（决定下一步）
 ↓
Tool Selection（选工具）
 ↓
Tool（执行，如 ST_DWithin）
 ↓
Observation（观察结果）
 ↓
LLM（再推理）
 ↓
Final Answer
```

---

## 2. 一个空间 Agent 的例子

用户：

> 「帮我找长沙市距离地铁站 500 米以内的高校。」

Agent 自动决定：

```text
① 查询高校（调用 query_schools）
② 查询地铁站（调用 query_subway_stations）
③ ST_DWithin（空间计算：500 米内）
④ 整理结果
⑤ 返回地图
```

**LLM 负责决策，PostGIS 负责真正计算。** 这个思想非常重要。

---

## 3. Tool Calling

工具就是「函数」，Agent 通过函数调用（Tool Calling）来执行：

```text
工具示例：
  query_schools(city)          -> 高校列表
  query_subway(city)           -> 地铁站列表
  spatial_query(layer, filter) -> 空间查询
```

LLM 不直接算空间距离，而是「决定调哪个工具、传什么参数」，真正的计算交给工具（PostGIS）。

---

## 4. 动手清单

1. 画一遍 Agent 循环，标出「LLM 决策」和「工具执行」的边界。

2. 思考：如果 LLM 自己算「500 米内」，为什么不可靠？为什么要交给 PostGIS？

3. 挑战：Agent 的「Observation（观察结果）」为什么重要？没有它会怎样？

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| Agent | 推理 + 工具调用的循环 |
| Tool Calling | LLM 选工具、传参 |
| 分工 | LLM 决策，PostGIS 计算 |

**核心认知**：Agent 的价值在于「决策」与「执行」分离——LLM 决定做什么，工具（空间数据库、GIS 函数）精确地做。GIS 背景让你能设计出「空间工具」，这是普通后端做不到的。
