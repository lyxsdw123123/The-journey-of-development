# 1. PostGIS 空间查询

## 0. 一句话结论

**PostGIS 把 PostgreSQL 变成空间数据库——能用 SQL 做空间查询。核心是空间数据类型（POINT/LINESTRING/POLYGON…）、空间函数（ST_DWithin/ST_Intersects…）、空间索引（GiST）。这些才是 GeoAI 真正能调用的「工具」。**

---

## 1. 技术链

```text
PostgreSQL → PostGIS → 空间数据库
```

---

## 2. 空间数据类型

| 类型 | 含义 |
|------|------|
| POINT | 点（一个坐标） |
| LINESTRING | 线（道路、河流） |
| POLYGON | 面（建筑、地块） |
| MULTIPOINT | 多点 |
| MULTIPOLYGON | 多面 |

---

## 3. Geometry 与 Geography

| 类型 | 说明 |
|------|------|
| `Geometry` | 平面几何（投影坐标，计算快） |
| `Geography` | 球面地理（经纬度，考虑地球曲率） |

---

## 4. 核心空间函数

| 函数 | 作用 |
|------|------|
| `ST_DWithin` | 距离范围内（如 5000 米内） |
| `ST_Intersects` | 是否相交 |
| `ST_Contains` | 是否包含 |
| `ST_Within` | 是否被包含 |
| `ST_Distance` | 计算距离 |
| `ST_Buffer` | 生成缓冲区 |
| `ST_Intersection` | 求交集 |
| `ST_Centroid` | 求质心（中心点） |

典型查询：

```sql
SELECT *
FROM schools
WHERE ST_DWithin(
    geom,
    ST_SetSRID(ST_Point(112.93, 28.18), 4326),
    5000
);
```

解读：`ST_Point` 创建点 → `ST_SetSRID(..., 4326)` 指定 WGS84 坐标系 → `ST_DWithin(geom, 点, 5000)` 找 5000 米内的学校。

---

## 5. 动手清单

1. 装 PostgreSQL + PostGIS，建一张 `schools` 表（参考同目录 `1. PostGIS 空间查询.sql`）。

2. 分别试 `ST_DWithin`、`ST_Intersects`、`ST_Buffer` 三个函数。

3. 挑战：`ST_DWithin` 和 `ST_Distance` 有什么区别？为什么范围查询用 `ST_DWithin` 更高效（配合索引）？

---

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| 空间类型 | POINT/LINESTRING/POLYGON |
| 空间函数 | ST_DWithin/Intersects/Contains/… |
| 空间索引 | GiST |
| 坐标系 | SRID（4326 = WGS84） |

**核心认知**：PostGIS 把「空间计算」搬进数据库，让你不依赖 ArcGIS 也能用 SQL 完成空间分析。这是 GeoAI 的「空间能力底座」。
