# 2. 空间数据库与索引

## 0. 一句话结论

**不要只学 PostGIS API，要理解空间数据库的完整链路：GIS 数据 → 空间数据库 → 空间索引 → 空间查询 → 空间分析。关键是 GiST 空间索引、Geometry/Geography、SRID 坐标系。**

---

## 1. 完整链路

```text
GIS 数据
   ↓
空间数据库（PostGIS 存储）
   ↓
空间索引（GiST，加速查询）
   ↓
空间查询（ST_DWithin 等）
   ↓
空间分析（缓冲区、叠加、求交）
```

---

## 2. 空间索引 GiST

```sql
CREATE INDEX idx_geom ON schools USING GIST (geom);
```

- 空间索引用 **GiST**（通用搜索树），不是普通 B-tree。
- 让「找 5000 米内的点」这类范围查询，从「全表扫描」变成「只查附近候选」。

---

## 3. SRID 与坐标系

| 概念 | 说明 |
|------|------|
| SRID | 空间参考系标识（Spatial Reference ID） |
| 4326 | WGS84 经纬度（最常用） |
| 3857 | Web 墨卡托（地图瓦片常用） |

```sql
ST_SetSRID(geom, 4326)   -- 指定坐标系
```

坐标系不一致时，空间运算会出错——**必须先统一 SRID**。

---

## 4. 查询优化

```text
空间查询优化
  ├── 建 GiST 索引
  ├── 用 ST_DWithin 代替 ST_Distance < 阈值（DWithin 能用索引）
  ├── 统一 SRID
  └── 先粗筛（包围盒）再精算
```

---

## 5. 最终目标

> **不依赖 ArcGIS，也能通过 SQL 完成大量基础空间分析。**

---

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| 链路 | 数据→索引→查询→分析 |
| GiST | 空间索引，加速范围查询 |
| SRID | 坐标系标识，必须统一 |
| 优化 | DWithin + GiST + 统一 SRID |

**核心认知**：空间数据库的本质是「用索引把空间查询变快」。会建 GiST、统一 SRID、用对空间函数，海量地理数据也能秒级响应——这是 GeoAI 的性能基础。
