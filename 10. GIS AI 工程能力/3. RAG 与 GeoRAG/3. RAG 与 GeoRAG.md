# 3. RAG 与 GeoRAG

## 0. 一句话结论

**RAG（检索增强生成）不是「调一下 similarity_search」，而是一条完整链路：Documents → Chunk → Embedding → 向量库 → 相似检索 → Context → LLM。GeoRAG 把「空间数据」也纳入检索，让 LLM 回答空间问题。**

---

## 1. RAG 完整架构

```text
Documents（文档）
    ↓
Chunk（切块）
    ↓
Embedding（向量化）
    ↓
Vector Database（向量库）
    ↓
Similarity Search（相似检索）
    ↓
Context（检索到的上下文）
    ↓
LLM（结合上下文生成）
```

**不要停留在 `vectorstore.similarity_search()`**——理解每一步在做什么。

---

## 2. GeoRAG

普通 RAG 只检索「文本知识」，GeoRAG 同时检索「空间数据」：

```text
GIS 文档
+
空间数据（PostGIS）
+
遥感数据说明
+
规划资料
        ↓
      GeoRAG
        ↓
       LLM
```

例如：

> 「长沙有哪些高校位于湘江东侧？」

系统同时检索：

```text
文本知识（文档里的高校信息）
+
PostGIS 空间数据（高校坐标、湘江位置）
```

这比普通 RAG 更接近真正的 GeoAI。

---

## 3. RAG 的价值

| 问题 | RAG 解决 |
|------|----------|
| LLM 知识过时 | 检索最新文档 |
| 领域知识缺失 | 注入 GIS/规划资料 |
| 幻觉 | 用检索到的上下文约束回答 |

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| RAG | 检索 + 生成 |
| 链路 | 文档→块→向量→检索→上下文→LLM |
| GeoRAG | 文本 + 空间数据联合检索 |

**核心认知**：RAG 是「给 LLM 找参考资料」的机制。GeoRAG 的关键是：空间问题（湘江东侧）不能靠文本检索，必须查空间数据库——这正是 GIS 背景的独特价值。
