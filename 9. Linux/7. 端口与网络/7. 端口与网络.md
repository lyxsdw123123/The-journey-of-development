# 7. 端口与网络

## 0. 一句话结论

**端口是进程对外通信的通道。理解「IP + Port + Process」三者关系，才能看懂 `127.0.0.1:8000` 这类地址，排查「端口占用」「连不上」等问题。**

---

## 1. 常见端口

| 端口 | 服务 |
|------|------|
| 8000 | FastAPI / Uvicorn |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 80 | HTTP |
| 443 | HTTPS |

---

## 2. IP + Port + Process

```text
127.0.0.1:8000
```

表示：

```text
本机（IP）
  ↓
8000 端口
  ↓
某个服务（进程）
```

这会直接连接到你的 FastAPI 服务。

---

## 3. 查看端口的命令

```bash
ss -tlnp              # 查看监听中的端口
netstat -tlnp         # 老命令（部分系统用）
lsof -i :8000         # 看谁占用了 8000 端口
```

```bash
lsof -i :8000         # 查 8000 被哪个进程占用
kill <PID>            # 结束占用进程
```

---

## 4. 典型问题

| 现象 | 排查 |
|------|------|
| 启动服务报「端口被占用」 | `lsof -i :8000` 找占用进程 |
| 访问不到服务 | 检查端口是否监听、防火墙是否放行 |
| 容器里连不上数据库 | 检查服务名 / 端口映射（呼应 Docker 网络） |

---

## 5. 动手清单

1. 在 Linux 跑一个 FastAPI，用 `ss -tlnp` 确认它在监听 8000。

2. 再启动一个占用 8000 的程序，观察「端口被占用」报错，用 `lsof -i :8000` 找到它。

3. 挑战：`127.0.0.1:8000` 和 `0.0.0.0:8000` 有什么区别？（提示：回想 Dockerfile 那节）

---

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| 端口 | 进程对外通道 |
| 常用端口 | 8000/5432/6379/80/443 |
| 排错 | lsof/ss 查端口占用 |

**核心认知**：端口是「IP 之下的第二级地址」。服务连不上、端口冲突，是后端部署最常见的两类问题，会查端口就能快速定位。
