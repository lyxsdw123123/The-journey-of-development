# 5. 日志查看与排错

## 0. 一句话结论

**服务异常时，先看日志。核心命令：`tail -f` 实时看、`grep` 找错误、`docker logs -f` 看容器日志。**

---

## 1. 基础命令

```bash
tail -f app.log        # 实时跟踪日志（新增内容实时显示）
cat app.log            # 一次性输出整个文件
less app.log           # 分页查看（q 退出）
grep ERROR app.log     # 只找包含 ERROR 的行
```

---

## 2. 结合 grep 排错

```bash
grep ERROR app.log              # 找错误行
grep -i error app.log           # 忽略大小写
grep -r "FastAPI" .             # 递归搜索目录
grep ERROR app.log | tail -20   # 最近 20 条错误
```

---

## 3. Docker 日志

部署 FastAPI/PostgreSQL/Redis/Nginx 后，常用：

```bash
docker ps                        # 查看容器
docker logs container_name       # 查看日志
docker logs -f container_name    # 实时跟踪
docker logs fastapi | grep ERROR # 容器日志里找错误
```

---

## 4. 排错流程

```text
服务异常
  ↓
查看日志（tail -f / docker logs -f）
  ↓
grep ERROR
  ↓
定位异常
  ↓
检查代码 / 数据库 / Redis
```

---

## 5. 动手清单

1. 生成一个日志文件，用 `tail -f` 实时观察它被追加的过程。

2. 用 `grep` 从一个日志里筛出所有 ERROR。

3. 挑战：`tail -f` 和 `cat` 看日志有什么区别？为什么排错时用 `tail -f` 更方便？

---

## 6. 小结

| 命令 | 作用 |
|------|------|
| tail -f | 实时看日志 |
| cat/less | 看文件 |
| grep | 过滤关键词 |
| docker logs -f | 看容器日志 |

**核心认知**：日志是后端的「黑匣子」。服务挂了、报错了、变慢了，第一步永远是看日志——它能直接告诉你发生了什么。
