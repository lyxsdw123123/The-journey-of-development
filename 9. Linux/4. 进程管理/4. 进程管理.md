# 4. 进程管理

## 0. 一句话结论

**进程管理是排查后端问题的重要能力——用 `ps` 看进程、`top`/`htop` 看资源、`kill` 结束进程。**

---

## 1. 常用命令

```bash
ps aux          # 查看所有进程
top             # 实时查看 CPU/内存/进程/负载
htop            # top 的增强版（更直观，需安装）
kill <PID>      # 结束进程
kill -9 <PID>   # 强制结束
```

---

## 2. ps 与 top

```bash
ps aux | grep fastapi    # 找 fastapi 相关进程
```

`top` 实时显示：

```text
CPU
内存
进程
负载（load average）
```

---

## 3. 排错流程

你的 FastAPI 服务突然 CPU 100%，第一反应应该是：

```text
服务器
  ↓
查看进程（ps / top）
  ↓
查看 CPU / 内存占用
  ↓
定位问题进程
  ↓
查看日志
```

```bash
top                          # 看谁在吃 CPU
ps aux | grep <进程名>        # 找进程 PID
kill <PID>                   # 结束问题进程
```

---

## 4. 动手清单

1. 在 Linux 上跑一个 `python main.py`，用 `ps aux | grep python` 找到它的 PID。

2. 用 `kill <PID>` 结束它。

3. 挑战：`kill` 和 `kill -9` 有什么区别？为什么优先用不带 `-9` 的？

---

## 5. 小结

| 命令 | 作用 |
|------|------|
| ps | 查看进程 |
| top/htop | 实时看资源 |
| kill | 结束进程 |

**核心认知**：服务出问题（CPU 飙高、内存爆、卡死），先看进程、看资源、定位、再处理。这是后端排错的「第一反应」。
