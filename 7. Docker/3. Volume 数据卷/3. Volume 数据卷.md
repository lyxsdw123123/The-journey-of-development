# 3. Volume 数据卷

> 配套可运行脚本：`3. Volume 数据卷.py`

## 0. 一句话结论

**Volume（数据卷）让「数据独立于容器生命周期存在」——容器删了，数据还在。**

---

## 1. 问题：容器删除，数据丢失

```text
PostgreSQL Container
        ↓
     数据库（存在容器里）
```

```bash
docker rm postgres   # 数据库数据一起没了！
```

数据库、用户上传的文件、日志等，都不能随容器一起消失。

---

## 2. 解决：Volume

```text
Container
   ↓
Volume（独立存储）
   ↓
数据
```

容器删除后，Volume 还在，数据得以保留。

---

## 3. compose.yaml 里的 Volume

```yaml
volumes:
  postgres_data:

services:
  db:
    image: postgres
    volumes:
      - postgres_data:/var/lib/postgresql/data
```

解读：

| 配置 | 含义 |
|------|------|
| `postgres_data` | 声明的命名数据卷 |
| `/var/lib/postgresql/data` | 容器内 PG 数据目录 |
| 映射 | 把容器目录挂到数据卷 |

这样即使 `docker compose down` 删掉容器，`postgres_data` 卷里的数据还在。

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| Volume | 独立于容器的持久存储 |
| 挂载 | 容器目录 ↔ 数据卷 |
| 意义 | 容器可删，数据不丢 |

**核心认知**：容器是「可丢弃」的，数据是「要保留」的。Volume 把这两者分开——这是生产环境数据库、文件存储的必备知识。
