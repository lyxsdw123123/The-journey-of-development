# 1. 为什么需要 Docker

> 配套可运行脚本：`1. 为什么需要 Docker.py`

## 0. 一句话结论

**Docker 把「运行环境」也变成「项目的一部分」——环境用代码描述，任何机器一条命令就能复现整个后端系统。**

---

## 1. 没有 Docker 的痛点

部署一个 FastAPI + PostgreSQL + Redis 后端，需要：

```text
安装 Python → 创建虚拟环境 → pip install → 安装 PostgreSQL → 配置
→ 安装 Redis → 配置 → 安装 Nginx → 配置环境变量 → 启动 FastAPI
```

换一台电脑，又得重新来一遍，还容易版本不一致、环境打架。

---

## 2. Docker 的思想

> **把运行环境也变成项目的一部分。**

```text
项目
├── Python
├── FastAPI
├── PostgreSQL
├── Redis
├── Nginx
└── 配置
```

全部通过 `Dockerfile` / `compose.yaml` 描述，任何机器一条命令复现。

---

## 3. 最终目标架构

```text
                    ┌──────────────┐
                    │    Nginx     │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │   FastAPI    │
                    └───┬──────┬───┘
                        │      │
              ┌─────────┘      └─────────┐
              ↓                           ↓
       ┌──────────────┐           ┌──────────────┐
       │ PostgreSQL   │           │    Redis     │
       └──────────────┘           └──────────────┘
```

```bash
docker compose up
```

整个后端环境启动。

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 痛点 | 环境安装繁琐、易不一致 |
| Docker | 环境即代码，可复现 |
| 目标 | 一条命令启动整个系统 |

**核心认知**：Docker 解决的是「环境一致性」问题——开发、测试、生产用同一套环境描述，杜绝「我电脑上能跑」的尴尬。
