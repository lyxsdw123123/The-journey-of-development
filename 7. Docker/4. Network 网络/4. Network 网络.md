# 4. Network 网络

> 配套可运行脚本：`4. Network 网络.py`

## 0. 一句话结论

**多个容器靠 Docker Network 通信。FastAPI 访问 PostgreSQL 不写 `localhost`，而是写服务名 `db`——compose 会自动建网络并解析服务名。**

---

## 1. 多容器需要通信

```text
FastAPI
   │
   ├──── PostgreSQL
   │
   └──── Redis
```

---

## 2. 服务名代替 localhost

```text
错误：DATABASE_URL = postgresql://user:pwd@localhost:5432/app
正确：DATABASE_URL = postgresql://user:pwd@db:5432/app
```

因为 compose 里：

```yaml
services:
  api:
    ...
  db:
    image: postgres
```

在同一 compose 网络里，**`db` 就是 PostgreSQL 容器的服务名**。

---

## 3. 完整例子

```yaml
services:
  api:
    build: .
    environment:
      DATABASE_URL: postgresql://postgres:password@db:5432/app
      REDIS_URL: redis://redis:6379

  db:
    image: postgres:17

  redis:
    image: redis:latest
```

FastAPI 写 `@db`、`@redis`，Docker 网络会自动解析成对应容器地址。

---

## 4. 关键点

1. 容器间通信用**服务名**，不是 `localhost`。
2. `localhost` 在容器里指向「容器自己」，不是宿主机。
3. compose 自动创建一个网络，把 services 都连进去。
4. 这是写 `DATABASE_URL` / `REDIS_URL` 时**非常重要**的概念。

---

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| Network | 让容器互相访问 |
| 服务名 | 容器间通信的地址 |
| localhost | 容器里指向自己 |

**核心认知**：容器是「隔离的小世界」，跨容器通信要靠网络和「服务名」。理解这一点，配置 `DATABASE_URL` 就不会再卡壳。
