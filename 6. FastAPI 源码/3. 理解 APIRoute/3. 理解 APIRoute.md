# 3. 理解 APIRoute

> 配套可运行脚本：`3. 理解 APIRoute.py`

## 0. 一句话结论

**一个普通函数变成能处理 HTTP 请求的 Route，靠的是 `APIRoute`（`fastapi/routing.py`）。它不是简单的 `URL → function`，而是一条完整的处理链。**

---

## 1. 从函数到 Route

```text
URL
  ↓
Route（APIRoute）
  ↓
依赖解析
  ↓
参数解析（从 path/query/body 拿参数）
  ↓
Pydantic 验证
  ↓
调用 endpoint
  ↓
序列化
  ↓
Response
```

---

## 2. APIRoute 的关键属性

```python
@app.get("/users/{user_id}")
async def get_user(user_id: int, name: str = "Tom"):
    ...
```

注册后，这个 route 有：

| 属性 | 值 |
|------|-----|
| `path` | `/users/{user_id}` |
| `methods` | `{'GET'}` |
| `endpoint` | `get_user` 函数 |
| `dependant` | 解析出的参数/依赖信息 |

`dependant` 里：

```text
路径参数：user_id
查询参数：name
```

**关键**：APIRoute 在注册时就「解析」了函数签名，知道每个参数从哪来（path / query / body / header）。

```text
fastapi/routing.py  ->  APIRoute
```

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| APIRoute | 把函数包装成 Route |
| 注册时解析签名 | 知道每个参数从哪来 |
| 处理链 | 依赖 → 参数 → 验证 → endpoint → 序列化 |

**核心认知**：FastAPI 的「魔法」不在装饰器本身，而在 APIRoute 把「函数签名」翻译成「HTTP 处理流程」。看懂 APIRoute，就懂了 FastAPI 一半的机制。
