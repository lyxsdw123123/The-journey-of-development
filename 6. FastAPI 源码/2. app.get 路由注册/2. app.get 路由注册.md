# 2. app.get 路由注册

> 配套可运行脚本：`2. app.get 路由注册.py`

## 0. 一句话结论

**`@app.get("/users")` 不只是装饰器——它把「路径 + 方法 + endpoint 函数」注册成一个 `APIRoute`，存进 `app.routes` 路由表。请求来了就按路径匹配，调用对应 endpoint。**

---

## 1. 追一层：@app.get 做了什么

```python
@app.get("/users")
async def get_users():
    return {"message": "hello"}
```

追下去：

```text
@app.get("/users")
   ↓
app.get()
   ↓
路由注册
   ↓
APIRoute
   ↓
app.routes（路由表）
   ↓
请求到来 -> 找到对应 route -> 调用 endpoint
```

---

## 2. 关键实验：打印 app.routes

```python
for route in app.routes:
    print(route.path, route.methods, route.endpoint)
```

你会看到：

```text
/users  {'GET'}   <function get_users>
/users  {'POST'}  <function create_user>
```

（还有 FastAPI 自动加的 `/docs`、`/openapi.json` 等文档路由。）

从这一刻起，你从「会使用 FastAPI」进入「知道它怎么管理路由」。

---

## 3. 请求怎么被路由

```text
请求 GET /users
   ↓
匹配 app.routes 里的 route
   ↓
调用 route.endpoint（就是 get_users 函数）
   ↓
返回结果
```

用 TestClient 验证（脚本里真实执行了这个过程）：

```python
client = TestClient(app)
resp = client.get("/users")   # 200, {"message": "hello"}
```

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| `@app.get` | 装饰器，注册路由 |
| `APIRoute` | 一个路由对象 |
| `app.routes` | 路由表 |
| 匹配 | 请求按路径找到 endpoint |

**核心认知**：路由的本质是「一张路径 → 函数的映射表」。`@app.get` 就是往这张表里插一条记录。看懂 `app.routes`，就懂了 FastAPI 的路由管理。
