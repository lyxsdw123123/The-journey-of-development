# 1. 完整请求链：FastAPI 不是 Web 服务器

> 配套可运行脚本：`1. 完整请求链.py`

## 0. 一句话结论

**FastAPI 本身不是 Web 服务器——它是「ASGI 应用」。执行 `uvicorn main:app` 时，Uvicorn 负责监听 HTTP 并把请求转成 ASGI 调用，FastAPI 只负责处理。**

## 2. FastAPI 不是 Web 服务器

```bash
uvicorn main:app
```

实际上：

```text
Uvicorn  负责监听 HTTP，把请求转换成 ASGI 调用
   ↓
FastAPI app（ASGI 应用）
```

所以 `uvicorn main:app` 里：

- `uvicorn` = Web 服务器（ASGI 服务器）
- `main:app` = 你的 FastAPI 应用

---

## 3. ASGI 是什么

ASGI 应用就是一个 callable：

```python
async def app(scope, receive, send):
    ...
```

| 参数 | 含义 |
|------|------|
| `scope` | 请求元信息（类型、路径、headers） |
| `receive` | 接收请求体的异步函数 |
| `send` | 发送响应的异步函数 |

FastAPI 实现这个接口，所以 Uvicorn 能调用它——**服务器与应用通过 ASGI 解耦**。

## 6. 小结

| 概念 | 一句话 |
|------|--------|
| FastAPI | ASGI 应用，不是服务器 |
| Uvicorn | ASGI 服务器，监听 HTTP |
| ASGI | 服务器与应用的接口 |
| 请求链 | 客户端 → Uvicorn → ASGI → FastAPI → ... → 客户端 |

**核心认知**：先分清「服务器」和「应用」，是理解 FastAPI 一切的前提。之后追源码，都是在这条链上往深处走。
