# 6. 完整请求链回顾

> 配套可运行脚本：`6. 完整请求链回顾.py`

## 0. 一句话结论

**学完这一主题，你应该能不看源码，解释一次完整请求的每一站。看到 `@app.get("/users", response_model=User)`，脑子里浮现的不是「语法」，而是完整的处理流程。**

---

## 1. 完整请求链

```text
浏览器发送请求
  ↓
Uvicorn
  ↓
ASGI
  ↓
FastAPI
  ↓
Middleware
  ↓
Router（找到 APIRoute）
  ↓
解析 Depends（依赖图）
  ↓
解析请求参数
  ↓
Pydantic Validation
  ↓
调用 Endpoint
  ↓
Response Model
  ↓
Serialization
  ↓
ASGI Response
  ↓
客户端
```

---

## 2. 你到达的状态

看到：

```python
@app.get("/users", response_model=User)
async def get_users(db=Depends(get_db)):
    ...
```

你脑子里不再是「这是 FastAPI 的语法」，而是：

> **「这里注册了一个 APIRoute，它有 endpoint、response model 和 dependency graph。请求进来后，FastAPI 会先解析依赖和参数，验证完成后调用 endpoint，最后进行响应序列化。」**

---

## 3. 各层职责回顾

| 层 | 职责 |
|----|------|
| APIRoute | 路由：URL → endpoint |
| Depends | 依赖注入：解析依赖图 |
| Pydantic | 数据：解析 + 验证 + 序列化 |
| Endpoint | 你的业务函数 |

---

---

## 5. 小结

| 概念 | 一句话 |
|------|--------|
| 请求链 | Uvicorn → ASGI → FastAPI → Router → DI → Endpoint → 序列化 |
| 路由 | APIRoute |
| 依赖 | Depends |
| 数据 | Pydantic |

**核心认知**：这就是「从会用框架 → 理解框架」的关键转折点。FastAPI 不再是黑盒，而是一条你能逐站解释的处理流水线。
