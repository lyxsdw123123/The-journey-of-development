# 2. 生成器（Generator）

> 配套可运行脚本：`2. 生成器.py`

## 0. 一句话结论

**用 `yield` 的函数是「生成器」——它不会一次算出所有结果，而是「要一个、算一个、给一个」，边产边停，内存占用几乎不随数据量增长。**

---

## 1. 普通函数 vs 生成器

普通函数：

```python
def get_numbers():
    return [1, 2, 3, 4, 5]   # 一次性创建整个列表
```

```text
创建整个列表
    ↓
返回
内存：[1, 2, 3, 4, 5]  全部存在
```

生成器：

```python
def get_numbers():
    yield 1
    yield 2
    yield 3
```

```text
第一次：yield 1  暂停
第二次：yield 2  继续
第三次：yield 3  结束
```

**它不会一次生成所有数据**，而是逐个产出。

---

## 2. `yield` 的执行过程

```python
def get_numbers():
    print("开始")
    yield 1
    print("继续")
    yield 2
    print("结束")
    yield 3

for x in get_numbers():
    print(x)
```

`yield` 的关键：**函数执行到 `yield` 就「暂停」，把值交出去；下次 `next()` 从暂停处「继续」**。

```text
暂停 -> 产出 1 -> 继续 -> 产出 2 -> 继续 -> 产出 3 -> 结束
```

---

## 3. 为什么大数据需要生成器

例如 10 亿条 GIS 轨迹数据：

```text
trajectory.csv
1
2
3
...
1000000000
```

如果：

```python
data = read_all()   # 10 亿条 -> 几十 GB -> 直接爆内存
```

用生成器：

```python
def read_lines(file):
    for line in file:
        yield line
```

```text
读取第 1 行 -> 处理 -> 释放
读取第 2 行 -> 处理 -> 释放
...
```

**内存里永远只保留一条**。

---

## 4. 内存对比

```python
import sys
lst = list(range(1_000_000))
gen = (i for i in range(1_000_000))

print(sys.getsizeof(lst))   # ~8 MB（100 万个指针）
print(sys.getsizeof(gen))   # ~200 字节（只是一个生成器对象）
```

- 列表：把 100 万个元素全部存下。
- 生成器：只存「当前状态」，要一个才算一个。

---

## 5. FastAPI 里的流式传输

大文件下载不能一次读进内存，要分块（chunk）流式发送：

```python
async def file_stream():
    while True:
        chunk = file.read(1024)   # 每次读 1KB
        if not chunk:
            break
        yield chunk               # 边读边发
```

实现**流式传输**：内存只占一个 chunk 大小。

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| `yield` | 让函数变生成器，暂停/继续 |
| 惰性求值 | 要一个才算一个 |
| 内存 | 生成器只存当前状态 |
| 大数据 | 逐行/分块读取，不爆内存 |

**核心认知**：生成器是「惰性」的——不急着把结果全算出来，而是按需产出。处理大数据、大文件、无限序列时，它是唯一正确的选择。
