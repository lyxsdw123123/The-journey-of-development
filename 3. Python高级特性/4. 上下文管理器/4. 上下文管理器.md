# 4. 上下文管理器（Context Manager）

> 配套可运行脚本：`4. 上下文管理器.py`

## 0. 一句话结论

**上下文管理器配合 `with` 自动管理资源，等价于 `try/finally`——无论代码是否异常，资源都会被安全释放。**

---

## 1. `with` 与 `try/finally` 等价

典型：

```python
with open("a.txt") as f:
    data = f.read()
```

完全等价于：

```python
f = open("a.txt")
try:
    data = f.read()
finally:
    f.close()   # 无论是否异常，都会执行
```

保证：

```text
打开文件 -> 执行代码 -> 关闭文件
```

---

## 2. 自己实现上下文管理器

```python
class MyContext:
    def __enter__(self):
        print("进入")
        return self
    def __exit__(self, exc_type, exc, tb):
        print("退出")

with MyContext():
    print("运行")
```

输出：

```text
进入
运行
退出
```

---

## 3. 为什么后端重要：数据库连接

```python
with database.connection():
    query()
```

流程：

```text
获取连接 -> 执行 SQL -> 提交事务 -> 释放连接
```

即使 SQL 抛异常，`__exit__` 也会执行，**连接不会泄漏**。这是后端资源管理最核心的保障。

---

## 4. 异常也保证释放

```python
class SafeResource:
    def __enter__(self):
        print("打开资源")
        return self
    def __exit__(self, exc_type, exc, tb):
        print("关闭资源（异常也执行）")
        return False   # 不吞异常

try:
    with SafeResource():
        raise ValueError("出错了")
except ValueError as e:
    print(f"捕获到：{e}")
```

输出：

```text
打开资源
关闭资源（异常也执行）
捕获到：出错了
```

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| `with` | 等价于 `try/finally` |
| `__enter__` | 进入时准备资源 |
| `__exit__` | 退出时释放资源 |
| 后端价值 | 数据库连接等资源不泄漏 |

**核心认知**：上下文管理器 = 自动资源管理的语法糖。后端开发中，凡「拿到必须归还」的资源（连接、锁、文件），一律用 `with` 包裹。
