# 5. Python 类型系统

> 配套可运行脚本：`5. Python类型系统.py`

## 0. 一句话结论

**Python 是动态类型，但工程项目需要「类型提示（Type Hint）」来提升可读性与可维护性，并让 FastAPI 等框架自动完成参数解析、数据验证和 API 文档生成。**

---

## 1. 动态类型

```python
a = 10
a = "hello"   # 同一个变量，先 int 后 str，都不报错
```

动态类型：变量类型在运行时才确定，灵活，但大型项目里容易出错（函数参数/返回值到底该是什么类型？）。

---

## 2. 类型提示（Type Hint）

```python
def get_users() -> list[str]:   # 返回字符串列表
    return ["Tom", "Jack"]
```

意思：**返回「字符串列表」**。

传统写法（老项目常见）：

```python
from typing import List

def get_users() -> List[str]:
    return ["Tom", "Jack"]
```

> Python 3.9+ 推荐直接用内置 `list[str]`；`typing.List` 是历史写法，两者等价。

---

## 3. 类型提示只是「提示」

```python
def add(a: int, b: int) -> int:
    return a + b

import typing
print(typing.get_type_hints(add))   # {'a': int, 'b': int, 'return': int}
```

**类型提示在运行时并不强制**——传错类型也不会报错。它是给「人和工具」看的，用来提示、检查、生成文档。

---

## 4. FastAPI 为什么依赖类型

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int

@app.post("/user")
def create_user(user: User):
    return user
```

FastAPI 借助类型自动做三件事：

| 能力 | 说明 |
|------|------|
| 参数解析 | 把 JSON 转成 `User` 对象 |
| 数据验证 | 类型不对自动报错 |
| API 文档 | Swagger `/docs` 自动生成 |

```text
1. 参数解析：
   {"name": "Tom", "age": 20}  ->  User(name="Tom", age=20)

2. 数据验证：
   {"name": "Tom", "age": "abc"}  ->  报错（age 应是 int）

3. 自动生成 API 文档：
   Swagger /docs 自动出现 User 的 name:string、age:int
```

---

## 5. 数据模型：dataclass / pydantic

```python
from dataclasses import dataclass

@dataclass
class User:
    name: str
    age: int

u = User("Tom", 20)
```

用类型标注定义数据模型，字段和类型一目了然。FastAPI 用的 `pydantic.BaseModel` 就是这种思路的强化版（带验证、序列化）。

## 7. 小结

| 概念 | 一句话 |
|------|--------|
| 动态类型 | 变量类型运行时确定 |
| 类型提示 | 标注参数/返回类型，提升可读性 |
| 不强制 | 运行时不做类型检查 |
| FastAPI | 用类型做解析、验证、文档 |

**核心认知**：动态类型给灵活性，类型提示给确定性。后端工程里，类型提示是「代码即文档」的关键，也是 FastAPI/pydantic 自动化的基础。
